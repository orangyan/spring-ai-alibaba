## 一、类概述

### 1.1 设计目的

`DashScopeRerankOptions` 实现了Spring AI的`RerankOptions`接口，用于配置文档重排序模型的参数。重排序是RAG（检索增强生成）流程中的关键步骤，用于精排初筛后的文档。

### 1.2 完整定义

```java
package com.alibaba.cloud.ai.dashscope.rerank;

public class DashScopeRerankOptions implements RerankOptions {
    
    // 模型名称
    private String model = "gte-rerank";
    
    // 返回Top-N文档
    private Integer topN = 3;
    
    // 是否返回原始文档内容
    private Boolean returnDocuments = false;
    
    // Builder模式
    public static Builder builder() {
        return new Builder();
    }
}
```

### 1.3 重排序原理

```
原始查询
    ↓
向量检索（粗排）
    ↓
召回50-100条相关文档
    ↓
重排序模型（精排）
    ↓
返回Top-N（如Top-3）最相关文档
    ↓
LLM生成答案
```

### 1.4 设计特点

- ✅ **简洁高效**：只有3个配置字段
- ✅ **合理默认值**：开箱即用
- ✅ **Builder模式**：链式调用
- ✅ **RAG优化**：专为RAG场景设计

## 二、字段详解

### 2.1 model（模型名称）

**类型**：`String`  
**默认值**：`"gte-rerank"`  
**必填**：否（有默认值）

**说明**：
- 指定要使用的重排序模型
- 重排序模型专门训练用于文档相关性评分

**可用模型**：

| 模型名称 | 说明 | 最大文档数 | 特点 |
|---------|------|-----------|------|
| **gte-rerank** | 通用重排序模型 | 100 | 中英文，高精度 |
| **gte-rerank-hybrid** | 混合重排序模型 | 100 | 结合语义和关键词 |

**使用示例**：
```java
// 使用默认模型
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .build();  // 默认: gte-rerank

// 显式指定模型
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .withModel("gte-rerank")
    .build();

// 使用混合模型
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .withModel("gte-rerank-hybrid")
    .build();
```

---

### 2.2 topN（返回Top-N）

**类型**：`Integer`  
**默认值**：`3`  
**必填**：否（有默认值）

**说明**：
- 指定返回最相关的前N个文档
- 重排序后只保留相关性最高的文档
- 减少传递给LLM的上下文，降低成本

**取值建议**：

| 场景 | 推荐topN | 原因 |
|------|---------|------|
| **精确问答** | 1-3 | 只需最相关文档 |
| **综合回答** | 3-5 | 需要多角度信息 |
| **对比分析** | 5-10 | 需要多个来源 |

**使用示例**：
```java
// 只返回最相关的1条
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .withTopN(1)
    .build();

// 返回前5条（更多上下文）
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .withTopN(5)
    .build();

// 使用默认值3
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .build();  // topN = 3
```

**topN的影响**：
```
topN=1: 最精确，上下文最少，成本最低
topN=3: 平衡选择，适合大多数场景
topN=5: 更多上下文，答案更全面，成本较高
topN=10: 大量上下文，可能包含噪声
```

---

### 2.3 returnDocuments（返回文档内容）

**类型**：`Boolean`  
**默认值**：`false`  
**必填**：否（有默认值）

**说明**：
- 控制返回结果是否包含原始文档内容
- `false`：只返回文档索引和分数（默认，节省带宽）
- `true`：返回文档索引、分数和原始文本

**使用场景**：

**场景1：已有文档内容（推荐false）**
```java
// 你已经有文档内容，只需要排序
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .withReturnDocuments(false)  // 默认值
    .build();

// 重排序后，根据返回的索引提取文档
List<Document> rerankResult = rerankModel.rerank(query, documents, options);
```

**场景2：需要API返回文档（使用true）**
```java
// API返回完整文档内容
DashScopeRerankOptions options = DashScopeRerankOptions.builder()
    .withReturnDocuments(true)
    .build();
```

**为什么默认false？**
- 节省带宽：不重复传输文档内容
- 提升性能：减少数据传输时间
- 降低成本：减少网络流量

**什么时候用true？**
- 文档存储在远程，本地没有
- 需要API直接返回文档内容
- 简化客户端逻辑

### 3.2 RAG应用中使用

```java
public class RagWithRerank {
    
    private final VectorStore vectorStore;
    private final DashScopeRerankModel rerankModel;
    
    /**
     * 完整RAG流程
     */
    public String queryWithRerank(String userQuery) {
        // 1. 向量检索（粗排）：召回50条
        List<Document> candidates = vectorStore.similaritySearch(
            SearchRequest.query(userQuery).withTopK(50)
        );
        
        // 2. 重排序配置（精排）：只要Top-3
        DashScopeRerankOptions rerankOptions = 
            DashScopeRerankOptions.builder()
                .withTopN(3)
                .withReturnDocuments(false)
                .build();
        
        // 3. 重排序
        List<Document> rerankedDocs = rerankModel.rerank(
            userQuery,
            candidates,
            rerankOptions
        );
        
        // 4. 构建Prompt
        String context = rerankedDocs.stream()
            .map(Document::getText)
            .collect(Collectors.joining("\n\n"));
        
        String prompt = String.format(
            "根据以下内容回答问题：\n\n%s\n\n问题：%s",
            context,
            userQuery
        );
        
        // 5. LLM生成答案
        return chatModel.call(prompt);
    }
}
```

### 3.4 动态topN配置

```java
public class DynamicRerankConfig {
    
    /**
     * 根据问题类型动态调整topN
     */
    public DashScopeRerankOptions selectTopN(String query) {
        int topN;
        
        if (query.contains("什么是") || query.contains("who is")) {
            // 定义类问题：1-2条即可
            topN = 1;
        } else if (query.contains("如何") || query.contains("怎么")) {
            // 过程类问题：需要多步骤，3-5条
            topN = 5;
        } else if (query.contains("对比") || query.contains("compare")) {
            // 对比类问题：需要多个来源，5-10条
            topN = 10;
        } else {
            // 默认
            topN = 3;
        }
        
        return DashScopeRerankOptions.builder()
            .withTopN(topN)
            .build();
    }
}
```

### 4.2 成本优化

```java
public class CostOptimizer {
    
    /**
     * 计算不同topN的成本
     */
    public void analyzeCost(int candidateCount) {
        for (int topN : List.of(1, 3, 5, 10)) {
            // 重排序成本（假设按候选文档计费）
            double rerankCost = candidateCount * 0.001;  // $0.001/文档
            
            // LLM成本（按token计费）
            int avgTokensPerDoc = 500;
            int totalTokens = topN * avgTokensPerDoc;
            double llmCost = totalTokens * 0.00001;  // $0.00001/token
            
            double totalCost = rerankCost + llmCost;
            
            System.out.printf("Top-%d: 总成本 $%.4f (重排 $%.4f + LLM $%.4f)%n",
                topN, totalCost, rerankCost, llmCost);
        }
    }
}
```

Top-3: 总成本 $0.0650 (重排 $0.0500 + LLM $0.0150)
Top-5: 总成本 $0.0750 (重排 $0.0500 + LLM $0.0250)

## 五、注意事项

### 5.1 关键注意事项

| 注意事项 | 说明 |
|---------|------|
| **候选文档数** | 建议50-100条，太少效果不明显，太多影响性能 |
| **topN选择** | 通常3-5条即可，太多会增加LLM成本 |
| **returnDocuments** | 默认false节省带宽，除非必要不要设为true |
| **模型选择** | 默认模型已足够，除非有特殊需求 |
| **成本考虑** | 重排序按候选文档数计费，不是按topN |

---

### 5.2 常见问题

**Q1: 重排序和向量检索有什么区别？**
```
A: 
向量检索（粗排）：
- 快速召回大量候选文档
- 基于向量相似度
- 可能不够精确

重排序（精排）：
- 精确评分每个候选文档
- 基于复杂的相关性模型
- 更精确，但速度较慢

推荐流程：
1. 向量检索召回50-100条（快）
2. 重排序精选Top-3（准）
```

**Q2: topN设多少合适？**
```
A: 根据场景选择：
- 简单问答：topN=1-3
- 复杂问题：topN=3-5
- 综合分析：topN=5-10

平衡考虑：
- topN越大，答案越全面，但成本越高
- topN越小，答案越精确，但可能遗漏信息
```

**Q3: returnDocuments设为true有什么影响？**
```
A: 影响：
1. 增加响应数据量
2. 增加网络传输时间
3. 通常没必要（你已经有文档内容）

推荐：保持默认false
```

**Q4: 候选文档数多少合适？**
```
A: 建议50-100条：
- 太少（<20）：重排序效果不明显
- 太多（>200）：性能下降，成本增加
- 50-100：平衡效果和性能
```

**Q5: 重排序的成本如何？**
```
A: 按候选文档数计费，不是topN：
- 候选50条文档，topN=3 → 按50条计费
- 候选100条文档，topN=3 → 按100条计费

因此，候选文档数要合理控制。
```
