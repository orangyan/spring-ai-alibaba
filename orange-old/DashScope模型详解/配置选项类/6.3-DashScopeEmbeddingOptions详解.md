## 一、类概述

### 1.1 设计目的

`DashScopeEmbeddingOptions` 是Spring AI `EmbeddingOptions` 接口的实现，用于配置DashScope嵌入向量模型的参数。这是一个简洁的配置类，只包含3个核心字段。

### 1.2 完整定义

```java
package com.alibaba.cloud.ai.dashscope.embedding;

@JsonInclude(JsonInclude.Include.NON_NULL)
public class DashScopeEmbeddingOptions implements EmbeddingOptions {
    
    // 模型名称
    @JsonProperty("model")
    private String model;
    
    // 文本类型
    @JsonProperty("text_type")
    private String textType;
    
    // 向量维度
    @JsonProperty("dimensions")
    private Integer dimensions;
    
    // Builder模式
    public static Builder builder() {
        return new Builder();
    }
}
```

### 1.3 设计特点

- ✅ **简洁高效**：只有3个配置字段
- ✅ **Spring AI规范**：实现EmbeddingOptions接口
- ✅ **Builder模式**：链式调用
- ✅ **JSON序列化**：支持Jackson序列化

## 二、字段详解

### 2.1 model（模型名称）

**类型**：`String`  
**默认值**：`null`  
**必填**：✅ 是（实例化模型时必填）

**说明**：
- 指定要使用的Embedding模型
- 不同模型支持不同的维度和语言

**可用模型**：

| 模型名称 | 维度 | 语言 | 适用场景 |
|---------|------|------|---------|
| **text-embedding-v1** | 1536 | 中英文 | 通用文本嵌入 |
| **text-embedding-v2** | 1536 | 中英文 | 改进版通用嵌入 |
| **text-embedding-v3** | 1024/768/512 | 中英文 | 灵活维度，性能更优 |

**使用示例**：
```java
// 使用v2模型
DashScopeEmbeddingOptions options = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v2")
    .build();

// 使用v3模型
DashScopeEmbeddingOptions options = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v3")
    .build();
```

---

### 2.2 textType（文本类型）

**类型**：`String`  
**默认值**：`null`  
**必填**：否

**说明**：
- 指定输入文本的类型，帮助模型优化嵌入向量
- 不同文本类型会影响向量的质量

**可选值**：

| 文本类型 | 值 | 说明 | 使用场景 |
|---------|---|------|---------|
| **查询文本** | `query` | 用户查询或问题 | 搜索查询、问答系统 |
| **文档文本** | `document` | 知识库文档 | 文档索引、知识库构建 |

**使用场景**：

**1. RAG应用（推荐区分）**：
```java
// 索引阶段：将文档向量化
DashScopeEmbeddingOptions docOptions = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v2")
    .withTextType("document")  // 文档类型
    .build();

// 查询阶段：将用户问题向量化
DashScopeEmbeddingOptions queryOptions = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v2")
    .withTextType("query")  // 查询类型
    .build();
```

**2. 通用场景（不指定）**：
```java
// 不指定textType，模型自动处理
DashScopeEmbeddingOptions options = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v2")
    .build();
```

**为什么要区分textType？**
- **查询优化**：query类型针对短文本、问题式语句优化
- **文档优化**：document类型针对长文本、陈述式语句优化
- **相似度提升**：区分类型可以提高查询与文档的匹配准确度

---

### 2.3 dimensions（向量维度）

**类型**：`Integer`  
**默认值**：`null`（使用模型默认维度）  
**必填**：否

**说明**：
- 指定输出向量的维度
- 只有部分模型（如v3）支持自定义维度
- 较低维度可以减少存储和计算成本

**支持维度的模型**：

| 模型 | 默认维度 | 支持的自定义维度 |
|------|---------|----------------|
| text-embedding-v1 | 1536 | ❌ 不支持自定义 |
| text-embedding-v2 | 1536 | ❌ 不支持自定义 |
| text-embedding-v3 | 1024 | ✅ 1024, 768, 512 |

**使用示例**：
```java
// v3模型，使用默认1024维
DashScopeEmbeddingOptions options = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v3")
    .build();

// v3模型，自定义512维（节省存储）
DashScopeEmbeddingOptions options = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v3")
    .withDimensions(512)
    .build();

// v3模型，768维（平衡性能和存储）
DashScopeEmbeddingOptions options = DashScopeEmbeddingOptions.builder()
    .withModel("text-embedding-v3")
    .withDimensions(768)
    .build();
```

**维度选择建议**：

| 场景 | 推荐维度 | 原因 |
|------|---------|------|
| 高精度RAG | 1024 | 最高质量 |
| 平衡场景 | 768 | 性能与存储平衡 |
| 大规模存储 | 512 | 节省存储空间 |

### 4.2 维度优化

```java
public class DimensionOptimizer {
    
    /**
     * 计算存储成本
     */
    public long calculateStorageCost(int documentCount, int dimensions) {
        // 假设每个float 4字节
        return (long) documentCount * dimensions * 4;
    }
    
    /**
     * 推荐维度
     */
    public int recommendDimensions(int documentCount) {
        long storage512 = calculateStorageCost(documentCount, 512);
        long storage768 = calculateStorageCost(documentCount, 768);
        long storage1024 = calculateStorageCost(documentCount, 1024);
        
        System.out.printf("512维存储: %.2f MB%n", storage512 / 1024.0 / 1024);
        System.out.printf("768维存储: %.2f MB%n", storage768 / 1024.0 / 1024);
        System.out.printf("1024维存储: %.2f MB%n", storage1024 / 1024.0 / 1024);
        
        // 根据存储预算决定
        if (storage1024 < 1024 * 1024 * 1024) {  // < 1GB
            return 1024;
        } else if (storage768 < 1024 * 1024 * 1024) {
            return 768;
        } else {
            return 512;
        }
    }
}
```

### 4.3 配置验证

```java
public class OptionsValidator {
    
    /**
     * 验证配置
     */
    public void validate(DashScopeEmbeddingOptions options) {
        // 检查模型
        if (options.getModel() == null || options.getModel().isEmpty()) {
            throw new IllegalArgumentException("Model不能为空");
        }
        
        // 检查维度
        if (options.getDimensions() != null) {
            String model = options.getModel();
            Integer dimensions = options.getDimensions();
            
            if (model.equals("text-embedding-v3")) {
                if (dimensions != 512 && dimensions != 768 && dimensions != 1024) {
                    throw new IllegalArgumentException(
                        "v3模型dimensions只能是512、768或1024");
                }
            } else {
                throw new IllegalArgumentException(
                    "只有v3模型支持自定义dimensions");
            }
        }
        
        // 检查textType
        if (options.getTextType() != null) {
            String textType = options.getTextType();
            if (!textType.equals("query") && !textType.equals("document")) {
                throw new IllegalArgumentException(
                    "textType只能是'query'或'document'");
            }
        }
    }
}
```

## 五、注意事项

### 5.1 关键注意事项

| 注意事项 | 说明 |
|---------|------|
| **模型必填** | model字段必须指定 |
| **维度限制** | 只有v3模型支持自定义维度 |
| **维度一致性** | 查询和文档必须使用相同维度 |
| **textType可选** | 不指定也能工作，指定可能提升效果 |
| **不可变性** | 创建后尽量不要修改配置 |

---

### 5.2 常见问题

**Q1: 必须指定textType吗？**
```
A: 不必须。不指定时模型会自动处理。
   但在RAG场景下，区分query和document可能提升效果。
```

**Q2: 如何选择维度？**
```
A: 考虑因素：
   1. 数据量：大数据量选低维度
   2. 精度要求：高精度选高维度
   3. 存储预算：有限预算选低维度
   
   推荐：
   - < 1万条: 1024维
   - 1-10万条: 768维
   - > 10万条: 512维
```

**Q3: v2和v3有什么区别？**
```
A: 主要区别：
   - v2: 固定1536维，不可调整
   - v3: 默认1024维，可选512/768/1024
   - v3性能更优，更灵活
   
   推荐：新项目使用v3
```

**Q4: 维度对性能有什么影响？**
```
A: 影响：
   1. 存储空间：维度越高，占用越多
   2. 计算速度：维度越高，相似度计算越慢
   3. 精度：维度越高，理论精度越高
   
   示例（100万条文档）：
   - 512维: 约2GB存储
   - 768维: 约3GB存储
   - 1024维: 约4GB存储
```

**Q5: 可以混用不同维度吗？**
```
A: ❌ 不可以！
   查询向量和文档向量必须维度相同才能计算相似度。
   
   正确做法：
   - 索引时用1024维 → 查询时也用1024维
   - 索引时用512维 → 查询时也用512维
```
